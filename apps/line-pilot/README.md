# アイドル駅伝：LINE配信の接続テスト

全体LINEグループとチーム別LINEグループへの送り分けを確かめるための試作です。ゲームのルールやAIによる文章生成は、まだ組み込んでいません。

## 今できること

- 全体・特定チーム・全チーム個別の送り先を選ぶ。
- 本文と送り先をプレビューし、配信練習を記録する。
- LINEから接続されたグループに、名前と用途を付ける。
- 接続設定後、LINEにテキストを送信し、グループごとの受付結果を残す。

**検証状況：内部処理と模擬通信のテスト済み。実際のLINEへの到着は未検証です。** LINEでの試験が終わるまでは、本番用として扱いません。

## 画面を試す

Node.js 22以上で、このフォルダーから実行します。追加ライブラリのインストールは不要です。

```powershell
npm start
```

ブラウザーで http://127.0.0.1:4318 を開きます。

1. 「練習用の全体・チームA・Bを追加」を押す。
2. 送り先と本文を選び、「プレビューする」を押す。
3. 「練習として記録」を押し、配信履歴に正しい送り先だけが出ることを確認する。

練習ではLINEに送信せず、料金も発生しません。

## 実際のLINEで確認する手順

1. [LINE Official Account Manager](https://manager.line.biz/)でイベント用の公式アカウントを作成する。既存のものがあれば利用可能。
2. 公式アカウントの設定でMessaging APIを有効にする。
3. [LINE Developers Console](https://developers.line.biz/console/)で、そのチャンネルの「Allow bot to join group chats」を有効にする。
4. `.env.example`を`.env`としてコピーし、チャンネルシークレットとアクセストークンをそのファイル内に設定する。実送信を試すときだけ`LINE_LIVE=true`にする。接続情報はチャットやGitHubに貼り付けない。
5. 公開HTTPSの接続先を用意し、Webhook専用のローカルポート4319に接続する。管理画面のポート4318は公開しない。PC上の一時接続サービスを使うか、常設サーバーへの移行を後で決める。この試作は単一PC・単一プロセス用。
6. LINE側に`https://公開接続先/webhook`を登録し、「Verify」が成功することを確かめ、「Use webhook」を有効にする。
7. 試験用のLINEグループを二つ作り、公式アカウントを両方へ招待する。必要なら各グループで一度メッセージを送る。
8. 管理画面で「接続状況を更新」し、それぞれに「全体」「チーム」の用途を付ける。
9. 全体に一件、チームに一件のテスト文を送る。LINEアプリで、選んだグループだけに到着したことを確認する。
10. ボットを退出させたグループへの配信が止まることも確かめる。

LINEのAPIが受け付けたことと、参加者が実際に見たことは区別しています。履歴の「LINE受付済み」を確認した後、試験中はLINEアプリで到着も確認してください。通信エラーや処理中のまま再起動した場合は、受付結果を確認してから対処してください。この試作に自動再送はありません。

## 運用前に残っていること

- 実際の公式アカウント・複数グループでの接続試験。
- 公開HTTPSの接続先と、本番用の常設環境の選定。
- 配信数・料金プランの確認。グループへのプッシュ送信も人数で配信数が数えられる。
- 本番用の運営者ログイン、配信予約、監視、バックアップ、障害時の手動連絡。
- 得点・資金の台帳、ニュース生成、広告購入などとの接続。

管理画面はローカル専用、Webhookは別ポートです。LINEの署名を検証してからグループを登録します。グループIDと設定、運営が配信した本文・結果は`data/`に保存されます。参加者のチャット本文や個人LINE IDは保存しません。`.env`と`data/`はGit管理の対象外です。
