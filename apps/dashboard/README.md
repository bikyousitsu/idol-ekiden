# アイドル駅伝：ケイテキ!ニュースと運営画面

参加者：[トップ](https://idol-ekiden-control.coolmyna3.chatgpt.site)／[練習版](https://idol-ekiden-control.coolmyna3.chatgpt.site/demo)／[リハーサル](https://idol-ekiden-control.coolmyna3.chatgpt.site/rehearsal)。運営：[編集ページ](https://idol-ekiden-control.coolmyna3.chatgpt.site/admin)。

参加者はログイン不要。ニュース一覧、一記事一URL、要約・本文、架空の応援・考察・辛口コメント、ファン数・全組のGB、予定を見られます。Yahoo!ニュースの情報配置を参考にした独自の「ケイテキ!ニュース」です。

運営は担当別の運営ID＋パスコードでログインし、サーバーで運営権限を確認します。スタッフのChatGPT登録は不要。採点・報酬・購入・SNS・合同ロケ・スキャンダル・武道館、台帳の訂正・バックアップ、スタッフIDの管理、記事編集を行います。担当名付きの操作記録は共有DBに保存。会場・価格等は試運転用の仮案です。

## 初回・当日

手順は [画面の使い分け](../../docs/production/dashboard-pages.md) と [ニュース編集ガイド](../../docs/production/news-editorial-guide.md)。

- 所有者だけが初回管理者登録できます。Sitesで秘密設定した BOOTSTRAP_OWNER_EMAIL とログイン情報を照合します。登録後は ALLOW_OWNER_BOOTSTRAP を無効にする。設定値や実ユーザーIDをソースへ保存しない。
- 管理者は「スタッフID」で担当名・運営ID・権限を指定し、自動発行パスコードを本人へ個別配布します。パスコードは発行時だけ表示。再発行・無効化も管理者が行い、ID・パスコードを公開リポジトリへ入れません。本人用の管理者IDも発行でき、既存の所有者ChatGPTログインは発行・復旧用に残します。
- 運営IDのセッションは8時間。5回連続でログインに失敗すると15分待機します。共有IDを使わず、操作履歴の担当名で記録を追えるようにします。
- 練習・リハーサル・本番は別台帳。本番は600GB・ファン0人で開始。運営画面の初期選択は練習です。公開トップは本番を表示します。
- イベント時刻と進行は運営が更新。開催日未定のため自動進行しません。入力の時刻・上限・重複・残高・締切は計算で検証します。
- 採点の変更は理由を付けて置換・取消し、履歴を残す。最終得点は全6組の披露後に反映。
- 記事は記録から下書きを作り、人が編集・確認して公開。プレビューとLINE用コピーは保存済み記事を使用します。下書き保存は公開・共有の停止も兼ねます。
- 現行方式は16:30頃の首位1組。全体LINE架空投稿→記者突撃→森本がチームLINEで二択。口止め200GBなら記事0本、謝罪動画なら疑惑と評価の2記事。16:45対応締切・16:50結果確定は仮の目安。確認後に森本が記事URLを全体LINEへ手動投稿。旧全組方式の記録は保持する。
- 通信断は紙台帳、復旧後は受付番号を確認して登録。JSONバックアップは公開リポジトリへ入れない。

## 公開・編集の境界

公開GET /api/event は、ログイン済みでも台帳・操作担当・予告・共有鍵を返しません。書込みは拒否。運営APIは /api/admin/event と /api/admin/articles。認証・運営権限・同じサイトからの送信を確認します。台帳更新は台帳の版、記事更新は記事ごとの版とDBの版で競合を検知。拒否した原稿は画面に残します。

未公開記事は404。チーム限定予告は確認後に発行した192bitの鍵付きURLだけで閲覧でき、公開一覧には入りません。URLを転送された人も読めるため、チーム内だけで扱います。公開停止すると元のURLも読めません。編集プレビューには運営権限が必要。記事は検索登録なし・参照元を送らない設定です。

## 開発と確認

Node.js22.13以上。依存関係をインストールし、ローカルD1へ drizzle/0000_bright_spiral.sql を適用。npm run dev で起動。端末内の初回登録試験には、非公開の .dev.vars に受付フラグとローカルサインインのメールを設定します。

```text
node --test test/core.test.mjs test/news-content.test.mjs test/articles.test.mjs
node test/api-smoke.mjs
npm run build
```

API試験はlocalhostのリハーサル台帳だけを使い、元へ戻します。所有者本人の実ログインと管理者登録済み表示は確認済み。リハーサルG1の営業①で600→800GBを確認し、二重登録を試した段階です。既存の練習台帳にあるユーザー入力は保持しています。

スタッフ用の実IDはまだ発行していません。スタッフ実機でのログイン・入力、LINEでの表示、複数端末の同期・現地通信は未確認で、本番前に通し試験が必要です。LINE・AI APIの有料接続はありません。

数値の正本は [rules.json](../../data/rules.json)。変更後は計算・画面・資料をそろえる。Sitesでは既存 .openai/hosting.json の project_id を再利用し、保存したソースと同じビルドを公開します。DB・環境変数・秘密・実台帳は公開ソースから除外します。

## 時刻連動・労働・結果画面

管理者「予定・お題」で台帳別の開始時刻を変更。予定は schedule 操作として履歴に残し、参加者表示とサーバーの締切を連動。実施履歴・編集済み原稿は保持。

運営表示に6組の予告原稿を補完し、保存時に永続化。原稿だけでは得点や予告実施を変更しない。結果処理済みで原稿が欠落した場合にも補完できる。

①中央食堂前の台車リレー企画、②医学部噴水前合同ロケ。旧営業IDは過去台帳の再計算用に保持し、新規受付は拒否。 `/results` は全6組の最終採点・結果公開後だけ確定結果を表示する。

追加試験：`node --test test/revision.test.mjs`、ローカル運営の通し試験：`node test/revision-api-smoke.mjs`（終了時に台帳を復元）。

16:30頃の途中順位を管理者が一度固定し、首位1組にスキャンダル、最下位1組に神対応。入力担当が確認内容・成立結果を記録し、神対応成功は5万人。旧全組予告の履歴は再計算・完了を維持。小峰は会場A、たけは合同ロケ、侍は欠席、シャネル・スーダンはツアー開始から本部。ボンボ・グッドマンは記者→ファン役の訪問案。詳しい現行進行は ../../docs/production/latest-update.md。新方式API試験は node test/attention-api-smoke.mjs（localhostのみ・終了時に台帳を復元）。

## 架空投稿→取材→二択の現行方式

新規の対象抽選は rumor-apology-v2 を記録。「連絡原稿」は活動開始・投稿の森本事前許可・締切等を手動送信する文面。「スキャンダル進行」は対象の呼び名・架空投稿・記者台詞・森本の二択をコピーし、投稿/取材済みを記録する。口止めは200GB・記事なし。謝罪動画は全体LINE投稿済みと完成度の理由・−100000〜＋30000人を入力し、結果確定時に実際の増減を反映。疑惑と動画評価は別記事。以前の予告記録・編集済み原稿は保持する。検証は test/scandal-flow.test.mjs と localhost の test/scandal-api-smoke.mjs。

武道館の運用：運営「武道館のお題」で順位順・最大2組・目安1分の選択を進め、「武道館の進行」で開演10分前からの漫才→披露方法説明→現在順位→司会進行を確認する。[開演前台本](../../docs/production/live-opening-script.md)／[お題選択](../../docs/production/live-topic-selection.md)。

最新のチーム予定は [2組同時集合のツアー予定](../../docs/production/paired-tour-schedule.md)。労働バトルと合同ロケはどちらも2組同時集合。全組4会場＋両労働1回、各会場1組を維持し、Webのチーム予定とスタッフ予定を同じ正本から表示する。15分枠内の実施5分・移動10分は仮案で、B→D・A→Cなどを徒歩実測する。

労働バトルの最新内容：アイドルを台車に載せ、古参ファン全員が押すリレーに参加する設定。中央食堂前・2組同時の枠を維持する。使用台車の型番、人の乗車・走行の許容、乗る人数・交代方法、区画・距離と5分での成立は未確定。一般の荷物用台車の耐荷重だけでは乗車可と判断しない。仕様が未確認の台車に人を載せて試走しない。参考：[ピカのアルミ台車説明書](https://www.pica-corp.jp/wordpress/wp-content/uploads/2024/02/cf8e0217e128ba074cb5aae6430fdf33.pdf)は人や動物の乗車用途ではないと明記している（使用台車の型番は未確認）。勝敗・追加報酬は未決、各200GBは仮案。旧オタ芸の受取記録・残高を保持し、旧オタ芸受取済みの組は新しい名称で二重受取しない。
