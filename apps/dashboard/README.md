# アイドル駅伝 ダッシュボード

6組のファン数・順位・GB・完了会場、芸能ニュース、行動予定を表示し、運営が採点・報酬・購入・SNS・合同ロケ・スキャンダル・武道館ライブを記録します。

主催者確認用： https://idol-ekiden-control.coolmyna3.chatgpt.site

現在は本人限定。参加者に共有する前にサイトのアクセス設定と複数端末の試験を行います。所有者が非公開状態でサインインし、最初に管理者登録します。共有範囲を広げる前に初回登録用 `ALLOW_OWNER_BOOTSTRAP` を無効にしてください。管理者はスタッフのユーザーIDを追加できます。

## 当日の使い方

- 練習データは架空のサンプル。リハーサル・本番とは台帳が別です。本番は各組600GB・ファン0人で始まります。
- 5秒ごとに共有DBを読込みます。競合した更新は拒否し、最新画面を確認して再入力します。
- 進行段階とイベント時刻は運営が更新します。開催日が未定のため時刻は自動では進みません。
- 会場の4項目を登録。採点済みの場合は確認欄に4文字以上の訂正理由を付け、同じ採点を置換します。取消にも履歴を残します。
- 全組へ一度だけスキャンダル予告。対応締切16:45・結果反映16:50は仮案。遅延入力は「実施・受付時刻」で実際の受付を記録してください。
- 17:00は最後の会場得点とスキャンダル結果を照合してから定期収入を1回清算。17:20に取引終了、17:30から武道館ライブへ進めます。
- 3審査員×5項目の最終採点は全6組終了まで閲覧者へ返しません。「結果公開」で最終ファン数と順位を確定。
- ニュースは人が確認して公開。チーム限定の掲載予告は全体公開できません。「LINE用にコピー」して該当グループへ手動投稿します。LINE API・AI APIへは接続していません。
- 通信断は[紙の受付台帳](../../materials/print/reception-ledger.html)。復旧後に番号と二重登録を確認。

## バックアップとルール

「台帳・設定」からJSON保存。開始前・スキャンダル反映後・17時清算後・最終結果後に保存する案です。復元は管理者のみ。実台帳は入力者ID等を含むため公開GitHubに入れません。GBは現金と別のゲーム内通貨です。

数値の正本は [../../data/rules.json](../../data/rules.json)。`lib/rules.json`へコピーし、説明資料もそろえます。報酬・料金は試運転案。残高不足、上限、報酬重複、SNS間隔、締切、採点不足を検証します。実際の成否と点数は運営が判定。

## 開発・試験

Node.js 22.13以上で依存関係を入れ、`npm run dev`で起動。ローカルD1へ`drizzle/0000_bright_spiral.sql`を適用して使います。初回登録の試験は公開しない`.dev.vars`で`ALLOW_OWNER_BOOTSTRAP=true`を設定し、ローカルのサインイン画面で登録。

```text
node --test test/core.test.mjs
node test/api-smoke.mjs
npm run build
```

API試験はlocalhost / 127.0.0.1のリハーサル台帳だけを使い、終了時に元へ戻します。DB・環境変数・実台帳は共有ソースから除外。既存の`.openai/hosting.json`のサイトIDを再利用し、保存したソースと同じビルドを配信します。

本番前には本人のログイン、スタッフ権限、参加者の閲覧と同期、会場通信、バックアップ復旧を通しで確認してください。
